# PoC 計画: promptfoo（LLM セキュリティ・品質評価）の使い勝手検証

OSS の LLM 評価／レッドチーミングツール **promptfoo** の**使い勝手・導入コスト・検出力**を
検証し、**AI 機能を QA でどう評価・レッドチームできるか**を現場に共有するための素材を作る。

- RedAmon（API を外から攻撃）とは層が違い、promptfoo は **LLM の入出力そのもの**を試す。
- このフェーズで確かめるのは **ツール（promptfoo）の評価**であって、特定プロダクトの診断ではない。
- RedAmon の検証は別計画 [redamon.md](./redamon.md) で扱う。

## 安全境界（最重要・先に固定する）

| 区分              | 内容                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| ✅ 対象にしてよい | **自作の練習用プロンプト**（ローカルで用意するシステムプロンプト）。使う LLM は自分の API キー経由 |
| ❌ 対象にしない   | 実プロダクトのシステムプロンプト・社外秘データ、業務アカウント、第三者サービスへの実到達           |

- red-team で生成される**敵対的プロンプトはローカル評価のみ**で使い、外部に投稿・送信しない。
- 有害カテゴリのテストは promptfoo の既定プラグイン範囲に留め、**学習・評価目的**に限定する。
- API キーはこの PoC 用に**最小限**にし、**月の利用上限を設定**する。

## 対象

| # | 対象                                                                   | 位置づけ     | 備考                                               |
| - | ---------------------------------------------------------------------- | ------------ | -------------------------------------------------- |
| 1 | 自作の練習プロンプト（例: 社外秘を漏らさないカスタマー問い合わせ Bot） | 主ターゲット | 守らせたいルールを明示でき、破れたかを採点しやすい |
| 2 | プロバイダ: Anthropic `claude-haiku-5-5`                               | 実行モデル   | 安価なモデルから試す。必要に応じて上位モデルへ     |

- 作業ディレクトリは `poc/promptfoo/`（promptfoo の設定・ケースはここに置き、追跡する）。
- 接続先は Anthropic API のみ。練習プロンプト・データは外部に出さない。

## ツール

- promptfoo（本家: <https://github.com/promptfoo/promptfoo> 、MIT）。`npx promptfoo@latest` で実行（Node が必要）。
- 2 系統を試す:
  - **eval**: 出力品質・回帰テスト（`promptfooconfig.yaml` にケース＋ `assert` で期待を検証）
  - **redteam**: 脆弱性テスト（prompt injection / jailbreak / PII 漏洩 / 有害出力などの敵対入力を自動生成）

## 手順（フェーズ）

| フェーズ              | 内容                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| 0. 準備               | Node/npx 確認。Anthropic API キー発行＋**月の利用上限（例 $10）**。`claude-haiku-5-5` から |
| 1. 練習プロンプト作成 | 守らせたいルール（例: 社外秘を言わない／役割を逸脱しない）を持つシステムプロンプトを自作   |
| 2. eval 設定          | `promptfooconfig.yaml` に数ケースを書き、`assert` で期待する挙動を検証                     |
| 3. redteam            | `promptfoo redteam init/run` で敵対入力を自動生成し、ルール破りを検出                      |
| 4. 評価               | 下の記録テンプレートに沿って記録。どの攻撃でルールが破れたかを整理                         |
| 5. まとめ             | 現場共有用のまとめ＋ Qiita 下書き                                                          |

## 記録テンプレート（現場共有のため）

| 観点       | 記録すること                                              |
| ---------- | --------------------------------------------------------- |
| 導入コスト | 起動までの時間・手順のつまずき・Node/依存のセットアップ   |
| 使い勝手   | 設定 YAML の書きやすさ・CLI/レポートの分かりやすさ        |
| 検出力     | どんな攻撃（injection/jailbreak/PII 等）を拾えたか        |
| 誤検知     | 問題ない出力を「破れた」と誤判定しないか                  |
| コスト     | 実際にかかった API 料金・1 回の実行時間                   |
| CI 適合性  | 定期実行・CI 組み込みに向くか（回帰テストとして使えるか） |
| 総評       | AI 機能の QA に取り込む価値・導入条件・次アクション       |

## やらないこと

- 実プロダクトのプロンプト・社外秘データの使用。
- 外部サービス（SNS 投稿・外部 API 等）への実到達。
- RedAmon の検証（別計画 [redamon.md](./redamon.md) で扱う）。
